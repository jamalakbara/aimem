## Decisions

1. **Server-rendered HTML instead of Next.js (changes 10 §7, 11 §1–2).** The local viewer is a new package `packages/viewer` (`@aimem/viewer`): `node:http`, HTML templates, one CSS file and one small script. It depends on `core` and `schema` only; the CLI loads it lazily. Next.js stays the choice for the team app in M6. Reason: `next` + `react` + `react-dom` install 338 MB and 10,362 files into a CLI that only needs to show files from one folder. Cost: M6 reuses the rendering rules, markdown renderer, URLs and tests, but not the page templates.
2. **`markdown-it` instead of remark/rehype (changes 10 §7 and the wording of 09 T5).** Measured on hostile 200 KB bodies (below): remark blocks the process for more than 20 s on two of 16 inputs; `markdown-it` needs at most 0.9 s on any. `html: false`, `linkify` off, images rendered as a text link. The renderer overrides every rule that writes HTML: tags come from a fixed allow-list, and so do attributes (`href`, `rel`, fixed `class` values, an integer `start`, and the constants `scope="col"` and `tabindex="0"`; no `style`, `title`, `id` or fence language). An author's `href` must parse with `URL` without a base and have protocol `https:`, `http:` or `mailto:`; `//host`, relative and all other links become text. Links to records are generated by the viewer from `[[ref]]` and ids. External links get `rel="noopener noreferrer"`. An unknown token type renders as escaped text. A test parses the output of the whole XSS corpus and fails on any tag or attribute outside the lists. The CSP is the second layer. **This replaces a sanitizer, so 09 T5 changes** from "HTML disabled + sanitizer" to "HTML disabled + allow-listed renderer output, checked in a parsed DOM".
3. **Import page (13 says "Import/upload page").** A guide to `aimem import` and `aimem sources`, with no upload. The local mode is read-only (10 §2), and a browser upload would need a write path, CSRF protection and an author identity. Upload moves to M6.
4. **Review queue.** 22 lists a web review queue under M5; 13 lists it under M6. 13 wins. M5 shows the unreviewed counts and a trust filter.
5. **Local access.** 127.0.0.1 only and no login (10 §2). No `--host` option at all in M5, so the viewer cannot be exposed by mistake. Anyone logged in to the same computer can open it while it runs; the docs say so.
6. **Search is keyword search.** The viewer never loads an embedding model or calls an LLM, so its order can differ from the hybrid `aimem search`. Tests compare with core `search()`.

## What the code and measurements show

Checked on `main` `b518720`, Node 26, 4 vCPU; synthetic notebook of 5,000 memories of about 150 words. Measured once each, so treat them as orders of magnitude.

| Finding | Consequence |
|---|---|
| `loadProjectIndex` takes 1.3–1.5 s and reads every file | Cached in memory; never per request |
| `stat` of 5,000 files in parallel takes 68 ms (serial 339 ms) | Change check on every request is affordable |
| `search()` takes 190–240 ms and returns 10 hits by default | Pass an explicit limit, paginate in the viewer |
| `search()`/`filterRecords()` hide `done`, `cancelled`, `superseded`, `rejected`, `retired` | Boards and timelines pass `includeSuperseded`; search has an "Include closed" option |
| `reviewQueue()` takes 1.8 s, `summarizeNotebook()` 9 ms | Dashboard counts come from `summarizeNotebook()` without its `live` argument (no Git) |
| A file that disappears while loading, a dangling symlink, or a folder named `*.md` makes `loadIndex` reject; a FIFO makes it hang | Entries are checked before they are opened (5.1, Cache) |
| A symlinked record or a symlinked type folder is followed | Left out of the viewer, with a problem card |
| Two local files with one id are both indexed and not reported in `duplicates` | The record page lists both instead of picking one silently |
| `node:http` accepts a missing `Host` (HTTP/1.0), two `Host` headers and absolute targets | The guard checks them itself (5.1) |
| `aimem serve web` exits 2 with `USAGE`; `action()` runs no heartbeat, call log or refresh | `serve` stays free of automatic side effects |

Markdown, 200 KB per input, 16 inputs (time to render):

| Input | remark + sanitize | `markdown-it` |
|---|---|---|
| repeated `>` | > 20 s (stopped) | 6 ms |
| repeated `*_` | > 20 s (stopped) | 243 ms |
| repeated `[^a] ` | 15.3 s | 179 ms |
| wide table | 10.5 s | 393 ms |
| repeated `![` | 483 ms | 903 ms |

`markdown-it` drops content nested deeper than its limit (600 nested list items kept 1,148 characters), so every record page also offers the body as escaped plain text. By default it also emits `data:` images, `//host` links, `style` on table cells, author-written `title` and the fence language as a class; decision 2 removes all of them.

## 5.1 — Server, guard and index cache

- `deps.serveWeb` in `bin.ts` next to `serveMcp`, imported lazily. Default port 4747, `--port 0` picks a free one. Does not open a browser (11 §2.1: only `core/git` and `core/process` start processes). Ctrl-C closes it.
- **Guard:** bind `127.0.0.1`, print the `http://127.0.0.1:<port>` URL. Exactly one `Host` header (counted in `rawHeaders`), equal to `localhost` or `127.0.0.1` with the actual port (port optional only for 80), otherwise 421. The target must start with one `/` (no absolute form, no `//`), otherwise 400; bad percent-encoding is 400, never an exception. Only GET and HEAD, otherwise 405 with `Allow`; CONNECT and upgrade sockets are closed. If `Sec-Fetch-Site` is `cross-site` or `same-site`, only `Sec-Fetch-Mode: navigate` with `Sec-Fetch-Dest: document` passes, otherwise 403. URL at most 2 KB, header and request timeouts of 10 s, at most 64 connections, request bodies are not read, no CORS headers. An error in a handler gives a 500 page without paths or stack.
- **Headers:** `Content-Security-Policy: default-src 'none'; style-src 'self'; script-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, `Cache-Control: no-store`. The two assets are constants in the package; no route maps a URL to a file path.
- **Cache:** core reads through a wrapped `Fs`. Before each read, `lstat` must say regular file of at most 10 MB whose real path stays inside its own `.aimem/`, and the opened file is checked again (`Fs.readRegular`); type folders that are links are skipped, and an `.aimem` that is a link is not followed. Anything else is not opened, becomes a problem card, and does not stop the load; the same for a file that is gone. Signature: path, mtime, ctime, size and inode of the record files and `project.yaml` of every source, sources resolved again each time; it is taken before and after a load and the load repeats once if they differ. One load at a time, 10 s limit; on failure the last good index plus a notice, 503 when there is none. Records left out here still appear in the CLI.
- **Core:** only optional fields are added to `Fs.stat`/`lstat` (`isFile`, `size`, `ctimeMs`, `ino`), and an optional `readRegular`. The same `loadIndex` failures affect the CLI and MCP; they get a separate core PR, which M5 does not wait for.
- **Read-only:** no lock, call log, vector refresh, Git or network. A test hashes the whole `.aimem/` tree before and after requesting every route, and a static scan allows no write or process API in the package.
- URLs follow 10 §3 (`/p/:project/…`); `/` redirects to the only project.

## 5.2–5.3 — Record page and search

- Record page: title, then type, status, trust (with its `verified` date) and the source of an imported record as separate text labels, freshness when stale or expired, body, roles, tags, paths as text, links, supersede chain, source and notebook label (`hub`, `repo:<name>`). **Copy reference** appears only when the script runs.
- Lookup by id from the index only. Moved stubs resolve as in `loadProjectIndex`; a stub whose target is not checked out says so. `[[ref]]` and record ids become links; `sourceWarnings()` and `problems` are shown as notices.
- Every value is escaped, including title, tags, author, paths and `source`. The raw file text is never served.
- One page formats at most 200,000 characters; longer bodies are shown as plain text, cut at 1,000,000 with a note, and at most five records that share an id are shown. Control characters and bidi overrides are not shown. A record that fails to render shows an error card; the rest of the page still loads.
- Search is a plain GET form that works without JavaScript; the script adds `Ctrl/⌘+K`. Query, filters and page live in the URL, so Back restores them; the selected hit is kept as a fragment so focus returns to it. Query at most 200 characters; 25 results per page.
- Every list shows trust as text, so an inferred draft cannot pass for a verified record.

## 5.4–5.7 — Lists, dashboard and sources

- Screens, wording and empty states follow Ajaw's spec (`No records yet`, `No matching records`, `Record not found`). Plain language, English only, strings in one file (10 §7).
- Desktop shows task columns, phones a grouped list. No drag, claims or live panel (M6).
- The lens is a URL parameter that filters dashboard and lists through `filterRecords({ roles })`. "Open tasks for me" needs an identity and is left for M6.
- Incidents are reached through search and browse by type; the incident explorer (10 §5.7) is not in 13's M5 list.
