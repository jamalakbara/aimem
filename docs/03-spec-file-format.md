# 03 — File Format Specification (v1)

Spec version: `aimem: 1`. This is the contract every tool (CLI, MCP, web, server, third-party) must follow.

## 1. Directory layout

See 02 §5. All record directories are flat (no nesting). A record's directory is determined by its type.

| Type | Directory | ID prefix | Tier |
|------|-----------|-----------|------|
| decision | `decisions/` | `dec` | core |
| task | `tasks/` | `tsk` | core |
| memory | `memory/` | `mem` | core |
| handoff | `handoffs/` | `hnd` | core |
| incident | `incidents/` | `inc` | extended |
| runbook | `runbooks/` | `run` | extended |
| schema | `schema/` | `sch` | extended |
| testcase | `tests/` | `tst` | extended |

## 2. Record file

A record is UTF-8 markdown: YAML frontmatter, then a body.

File name: `<id>-<slug>.md`. The slug is lowercase `a-z0-9-`, derived from the title, max 60 chars. **The `id` in frontmatter is authoritative**; the slug may drift if the title changes.

```markdown
---
aimem: 1
id: dec-7k3m9q2x
type: decision
title: Use Postgres for the ledger
summary: Ledger data lives in Postgres, not Mongo, for transactions and reporting joins.
status: accepted
trust: verified
roles: [dev, db, devops]
tags: [database, ledger]
repo: backend
paths: [services/ledger/**, db/migrations/**]
author: human:akbar
created: 2026-10-08T07:12:00Z
updated: 2026-10-08T07:12:00Z
verified: 2026-10-08
links: [tsk-3f9a1b2c, acme-platform:inc-8d2e4f6a]
supersedes: dec-2a4b6c8d
---

## Context
...
## Decision
...
## Consequences
...
```

### 2.1 Common frontmatter fields

| Field | Type | Req | Description |
|-------|------|-----|-------------|
| `aimem` | int | yes | Spec major version (1) |
| `id` | string | yes | `<prefix>-<8 base32 chars>`; unique within project |
| `type` | enum | yes | One of the 8 types |
| `title` | string | yes | ≤ 120 chars, human readable |
| `summary` | string | yes | **One line, ≤ 200 chars.** Used in briefings. Must stand alone. Length/one-line are checked by V009 (warning), not V002 |
| `status` | enum | yes | Lifecycle state; allowed values depend on type (§3) |
| `trust` | enum | yes | `verified` \| `agent` \| `inferred` |
| `roles` | string[] | yes | ≥ 1 role from the project's role list (or `all`). `all` is a record value meaning every role; it is not listed in `project.yaml` `roles` |
| `tags` | string[] | no | Free tags, lowercase kebab. Reserved: `pinned`, `imported`, `adopted`, `no-embed` (exclude from embeddings and `ask`; 15 §12) |
| `repo` | string | no | Repo name from `project.yaml`, or `all`. Default: the repo containing the file |
| `paths` | string[] | no | Glob patterns of code the record relates to. Used for ranking |
| `author` | string | yes | `human:<handle>` or `agent:<tool>[:<model>]` |
| `created` | datetime | yes | UTC ISO-8601 |
| `updated` | datetime | yes | UTC ISO-8601; set by tools on write |
| `verified` | date | no | Last date a human confirmed it is still true |
| `links` | ref[] | no | Related records (local or global refs) |
| `supersedes` | ref | no | Record this replaces |
| `superseded_by` | ref | no | Set by `aimem supersede` on the old record |
| `expires` | date | no | After this date the record is treated as stale |
| `external` | object[] | no | Links to outside systems: `{system: jira, id: ABC-12, url: ...}` |
| `managed_by` | enum | no | `notebook` (default) or `external`. External records are owned by their source and updated one-way from it (16 §2) |
| `source` | object | if external | `{system, id, url, row?, version, content_sha, synced_at, imported_by, state}`. `system`: `google-doc` \| `google-sheet` \| `odoo` (reserved, deferred) \| `upload`; `state`: `ok` \| `missing` \| `error`. (`external` above = informational links; `source` = ownership) |
| `evidence` | string[] | no | Where an `inferred` record came from (file paths, commit SHAs, URLs). Set by `aimem adopt`; used for idempotency (08 §2) |

### 2.2 ID rules
- 8 characters from `0123456789abcdefghjkmnpqrstvwxyz` (Crockford base32, lowercase), random.
- Generated by tools; never by counters (avoids cross-branch collisions).
- `validate` fails on duplicate IDs within a project (including hub).
- Global ref form: `<project>:<id>`.

### 2.3 Body rules
- Markdown, any length, but records **should be short** (guideline: ≤ 400 words; split otherwise).
- The first paragraph should not repeat the summary.
- No secrets, tokens, credentials, or personal data (see 09).
- Relative links to repo files allowed (`../../src/x.ts`). Prefer `paths:` for code relations.

## 3. Types: required fields, statuses, body template

### 3.1 decision
- Statuses: `proposed` → `accepted` | `rejected`; later `superseded` | `deprecated`.
- Body sections: `## Context`, `## Decision`, `## Consequences`, optional `## Alternatives`.
- Extra fields: `decided_by: [handles]` (optional).
- Rule: if `supersedes` is set, the old record must become `superseded` with `superseded_by`.

### 3.2 task
- Statuses: `open`, `in_progress`, `blocked`, `review`, `done`, `cancelled`.
- Extra fields: `assignee` (handle, optional), `priority` (`p0`..`p3`, default `p2`), `blocked_by: [ref]`, `due` (date).
- Body sections: `## Goal`, `## Acceptance criteria` (checklist), `## Notes`.
- **Claims are not stored here.** "Currently claimed" is derived from live state (07). `in_progress` is a durable status set when work actually starts.

### 3.3 memory
A fact worth remembering that is not a decision (gotcha, constraint, how-something-really-works).
- Statuses: `active`, `stale`, `superseded`.
- Extra fields: `kind` (optional): `gotcha` \| `constraint` \| `howto` \| `fact` \| `preference`.
- Body: free; start with the fact itself, then why we know it and how to verify.
- Default freshness window: 90 days since `verified` (or `created`) → shown as stale.

### 3.4 handoff
- Immutable by convention: tools refuse to edit a handoff body without `--force`, but git history is not policed in v1.
- Statuses: `final`.
- Extra fields: `session: <string>` (optional id), `task: ref` (optional), `branch: string` (optional).
- File name includes date: `hnd-<id>-<yyyymmdd>-<slug>.md`.
- Body sections (all required, may be "none"): `## Done`, `## Not done`, `## Next`, `## Blocked`, `## Notes for next agent`.

### 3.5 incident (extended)
- Statuses: `investigating`, `mitigated`, `resolved`, `postmortem_done`.
- Extra fields: `severity` (`sev1`..`sev4`), `started`, `resolved_at`, `services: [string]`, `root_cause_category` (free).
- Body: `## Impact`, `## Timeline`, `## Root cause`, `## Fix`, `## Prevention`.

### 3.6 runbook (extended)
- Statuses: `active`, `deprecated`.
- Extra fields: `last_tested` (date), `owner` (handle).
- Body: `## When to use`, `## Steps` (numbered), `## Rollback`, `## Verify`.

### 3.7 schema (extended; database/data notes)
- Statuses: `active`, `deprecated`, `superseded`.
- Extra fields: `datastore` (e.g. `postgres:ledger`), `objects: [string]` (tables/collections).
- Body: `## Shape`, `## Invariants`, `## Migration notes`, `## Gotchas`.

### 3.8 testcase (extended; QA)
- Statuses: `draft`, `ready`, `passing`, `failing`, `retired`.
- Extra fields: `covers: [ref]` (tasks/decisions), `automation` (path or `manual`).
- Body: `## Preconditions`, `## Steps`, `## Expected`, `## Last result`.

## 4. Status vocabulary summary

| Type | Allowed statuses | Default on create |
|------|------------------|-------------------|
| decision | proposed, accepted, rejected, superseded, deprecated | proposed |
| task | open, in_progress, blocked, review, done, cancelled | open |
| memory | active, stale, superseded | active |
| handoff | final | final |
| incident | investigating, mitigated, resolved, postmortem_done | investigating |
| runbook | active, deprecated | active |
| schema | active, deprecated, superseded | active |
| testcase | draft, ready, passing, failing, retired | draft |

"Default on create" applies when a tool creates a record without an explicit status (e.g. `aimem add` without `--status`).

## 5. Trust levels

| Trust | Meaning | Who sets | Ranking weight |
|-------|---------|----------|----------------|
| `verified` | A human confirmed it | `aimem verify`, or a human-authored record | 1.0 |
| `agent` | Written by an agent, not yet reviewed | default for agent writes | 0.7 |
| `inferred` | Derived by `aimem adopt` scanning existing artifacts | `adopt` | 0.4 |

Display rule: briefings and the web app always label non-verified records.

## 6. `project.yaml`

```yaml
aimem: 1
project: acme-platform            # slug, required
name: Acme Platform               # display name
mode: team                        # solo | team | team-realtime
sync: git                         # none | git | server

repo: backend                     # name of THIS repo within the project
repos:                            # optional; the project's repos (for multi-repo)
  - name: frontend
    url: git@github.com:acme/frontend.git
  - name: backend
    url: git@github.com:acme/backend.git
  - name: infra
    url: git@github.com:acme/infra.git
hub:                              # optional; central repo for cross-repo knowledge
  url: git@github.com:acme/project-hub.git
  path: .aimem                    # default

roles: [dev, pm, qa, db, devops, analyst]   # extend as needed

members:                          # used by web app / server for role views and attribution
  - handle: akbar
    roles: [dev, devops]
  - handle: rina
    roles: [dev]

write_policy:
  agent_commits: stage            # none | stage | commit | pr
  durable_requires_review: true   # decisions/runbooks/schema need review before trust=verified
  live_push: auto                 # auto | manual

freshness_days:                   # per-type staleness windows
  memory: 90
  runbook: 180
  schema: 120

briefing:
  budget_tokens: 4000
  max_handoffs: 2

retrieval:                        # full reference: 15 §11
  mode: hybrid                    # lexical | hybrid
  embeddings:
    provider: local               # local | openai-compatible | none
    allow_remote: false           # must be true to send content to a remote endpoint
  rerank: none                    # none | cross-encoder | llm
  llm:
    provider: none                # used only by `aimem ask` / rerank / query rewrite

connectors:                       # full reference: 16 §8 (no secrets here)
  google:
    inbox_folder_id: null
  # odoo: ...                     # deferred (ADR-016); see 16 §6

claims:
  ttl_minutes: 180                # claim expires if not heartbeated
  heartbeat_minutes: 20

server:                           # only if sync: server
  url: https://aimem.example.com
  project_id: acme-platform
```

Rules:
- `mode: solo` implies defaults `agent_commits: commit`, `durable_requires_review: false`, no members needed.
- Unknown keys are preserved and warned about, not rejected (forward compatibility).
- Secrets (tokens) are **never** stored here; use env vars (`AIMEM_TOKEN`) or the OS keychain.

## 7. Multi-repo and hub rules

1. **Single repo:** no `repos`, no `hub`. Everything is local.
2. **Several repos, no hub:** each repo has `.aimem/` with the same `project:` slug and the `repos:` list. A record lives in exactly one repo; others refer to it by global ref.
3. **Several repos + hub:** the hub repo contains the cross-repo records. Each repo sets `hub.url`. Rule of thumb: *affects one repo → that repo; affects several → hub.*
4. The record's `repo:` field says where it applies (`all` for cross-repo).
5. Resolution order: local → hub → sibling checkouts (`../<name>` or cache dir `~/.cache/aimem/<project>/<repo>`). Missing sources produce a warning, not an error.
6. IDs are unique per **project**, not per repo; `validate --project` checks across reachable sources.

## 8. `INDEX.md` (generated)

Generated by `aimem index`/after writes. Agents read it first. Contents:
- Project name, mode, repo list, hub.
- The 3-line protocol (see 06 §3).
- Counts per type/status.
- Pinned records (those with tag `pinned`), listed with `summary`.
- The 5 most recent handoffs (ref + summary).
- Open `p0`/`p1` tasks.
Never hand-edited; regenerated deterministically. Size limit 6 KB. Because it is a merge-conflict magnet, it is marked `merge=ours` in `.gitattributes` and regenerated by hook/CI (07 §1).

## 9. Validation rules (`aimem validate`)

| Code | Level | Rule |
|------|-------|------|
| V001 | error | Frontmatter missing or invalid YAML |
| V002 | error | Required field missing / wrong type |
| V003 | error | `type` does not match directory |
| V004 | error | Status not allowed for type |
| V005 | error | Duplicate `id` |
| V006 | error | `links`/`supersedes` point to unknown ref (warn if the target is in an unreachable source) |
| V007 | error | Supersede chain inconsistent (`supersedes` without `superseded_by` on target) |
| V008 | error | Possible secret detected in body (09 §4) |
| V009 | warn | `summary` missing/too long, or equals the title |
| V010 | warn | Record stale (past freshness window or `expires`) |
| V011 | warn | Two `accepted` decisions with overlapping `paths` and `tags` and no supersede link (possible conflict) |
| V012 | warn | Handoff missing a required section |
| V013 | warn | Body > 600 words |
| V014 | warn | `roles` contains unknown role |
| V015 | warn | File name slug/id mismatch |
| V016 | error | Spec major version newer than tool supports |
| V017 | warn | Externally-owned record body differs from `source.content_sha` (edited locally) |
| V018 | warn | Externally-owned record's source is missing or errored at last sync (`source.state != ok`) |

Exit codes: 0 ok, 1 warnings only (when `--strict`), 2 errors.

## 10. Compatibility and evolution

- Additive changes (new optional fields, new types) bump the **minor** spec version and are ignored by older tools.
- Breaking changes bump `aimem:` major; `aimem migrate` upgrades files.
- Tools must preserve unknown frontmatter keys on rewrite.
- Schemas never inject defaults: parsing a record or `project.yaml` adds no keys. Defaults (statuses §4, `priority: p2`, `project.yaml` values in §6) are applied by tools at the point of use.
- Type-specific fields in §3 are optional unless marked otherwise.
- JSON Schema for records and `project.yaml` is generated from the Zod schemas and published in `packages/schema/dist/`.
